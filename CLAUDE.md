\## 11. Полностью переработанный музыкальный плеер



Плеер должен быть компактным, минималистичным и постоянно находиться в левом нижнем углу экрана.

\### Внешний вид в обычном состоянии



В обычном состоянии плеер выглядит как небольшая горизонтальная панель с прозрачным или полупрозрачным тёмным фоном.



Расположение элементов слева направо:

2\. Кнопка Play/Pause по центру.

3\. Кнопка следующего трека (стрелка вправо).



Иконки должны быть минималистичными, без больших подписей.



Плеер должен иметь тонкую границу, небольшое скругление и лёгкий эффект стекла.



\### Перемещение плеера



Плеер должен поддерживать Drag \& Drop.



Я хочу иметь возможность:

\- Зажать плеер мышкой.

\- Перетащить его в любое место экрана.

\- Отпустить, чтобы зафиксировать положение.



На мобильных устройствах должно работать перемещение касанием.



Перетаскивание не должно мешать нажатию кнопок управления.



Позицию плеера желательно сохранять в localStorage, чтобы после обновления страницы он оставался там, куда я его переместил.



Не позволяй плееру случайно оказаться полностью за пределами экрана.



\### Интерактивная громкость



В обычном состоянии кнопка громкости не должна постоянно отображаться.



Когда пользователь наводит курсор на плеер, справа от него должна плавно появляться небольшая иконка динамика.



При наведении на иконку динамика:

\- Справа от неё плавно выдвигается дополнительная панель.

\- Внутри панели появляется горизонтальный слайдер громкости.

\- Можно регулировать громкость мышкой.

\- При перемещении ползунка громкость меняется сразу.

\- При уходе курсора панель плавно скрывается.



На мобильных устройствах вместо hover используй нажатие на иконку.



\### Поведение



\- Play/Pause должен работать без перезагрузки страницы.

\- Предыдущий и следующий трек должны переключать композиции.

\- Плеер не должен сбрасывать воспроизведение при переходе между секциями.

\- Сохранять громкость.

\- Отображать текущий статус воспроизведения.

\- Добавить аккуратные анимации кнопок.

\- Обеспечить поддержку клавиатуры и доступность элементов управления.



\## 12. Spotify и локальная музыка — два режима



Реализуй поддержку сразу двух источников музыки:



1\. Spotify.

2\. Локальные MP3-файлы.



Но при первом запуске сайта я НЕ буду добавлять MP3-файлы в проект.



Поэтому первоначально сайт должен попытаться использовать Spotify.



\### Приоритет источников



Сделай следующую логику:



1\. При загрузке сайта проверяется, настроен ли Spotify.

2\. Если Spotify настроен, попробовать инициализировать Spotify Player или Spotify Embed с моим плейлистом.

3\. Если Spotify не настроен, недоступен или не может обеспечить нужное воспроизведение, использовать локальный режим.

4\. Если локальных файлов пока нет, плеер должен оставаться в интерфейсе, но показывать аккуратное сообщение о необходимости добавить музыку.

5\. Не должно быть ошибок в консоли из-за отсутствия MP3-файлов.



Важно: не делай вид, что Spotify API позволяет бесплатно воспроизводить любые треки без ограничений.



Изучи реальные возможности Spotify Embed и Spotify Web Playback SDK. Если для полноценного управления Spotify необходим Premium, авторизация или другие условия, честно учитывай это.



Не пытайся обходить ограничения Spotify.



\### Локальная музыка



Создай специальную папку:



`public/music/`



Я в будущем буду самостоятельно закидывать туда MP3-файлы.



Например:



```text

public/

&#x20;   song1.mp3

&#x20;   song2.mp3

&#x20;   song3.mp3

```



Создай отдельный файл:



`src/data/localPlaylist.js`



В нём я смогу указывать свои композиции:



```js

&#x20;   title: "Song Name",
```

Если обложки нет, используй красивую стандартную заглушку.



Сделай понятную инструкцию в README.md:



1\. Куда закидывать MP3.

2\. Как добавлять треки в localPlaylist.js.

3\. Как добавлять обложки.

4\. Как переключаться между Spotify и локальной музыкой.



Не используй сервер для сканирования папки. На GitHub Pages это статический сайт, поэтому список локальных файлов должен задаваться через конфигурацию.



\### Важная деталь Spotify



Создай отдельный файл настроек:



`src/config/music.js`



В нём должны находиться:

## 15. Автоматическая настройка Git и резервное сохранение проекта  !!!!!!ОБЯЗАТЕЛЬНО ПРОЧИТАТЬ!!!!!!

Перед началом разработки самостоятельно настрой Git в папке проекта.

Я хочу, чтобы весь процесс разработки сопровождался автоматическим сохранением изменений.

### Первоначальная настройка

1. Проверь, установлен ли Git на компьютере.
2. Если Git установлен, проверь его конфигурацию.
3. Если Git не установлен, сообщи мне об этом и объясни, как установить его.
4. Инициализируй Git-репозиторий командой `git init`, если репозитория ещё нет.
5. Создай файл `.gitignore`.
6. Добавь в репозиторий исходный код и необходимые файлы проекта.
7. Сделай первый коммит с названием `Initial project setup`.

### Автоматические сохранения

Во время разработки регулярно создавай Git-коммиты.

Обязательно делай коммит после:
- Завершения первой страницы.
- Завершения Steam-секции.
- Завершения социальных сетей.
- Реализации музыкального плеера.
- Реализации Spotify и локального воспроизведения.
- Завершения адаптивной версии.
- Исправления крупных ошибок.
- Финального тестирования.

Используй понятные названия коммитов, например:
- `feat: create about page`
- `feat: add steam profile`
- `feat: implement music player`
- `feat: add social links`
- `fix: improve mobile layout`

### Защита изменений

- Никогда не выполняй `git reset --hard`.
- Никогда не используй `git clean -fd`.
- Не удаляй историю коммитов.
- Не перезаписывай предыдущие рабочие версии.
- Перед любыми потенциально опасными Git-операциями проверяй состояние репозитория.
- Не добавляй API-ключи, пароли, токены и другие секреты в коммиты.
- Не добавляй временные файлы, кэш и зависимости, которые не нужны в репозитории.

### GitHub

Если у меня уже есть GitHub-репозиторий, используй его после проверки.

Если удалённый репозиторий не настроен:
- Сначала настрой локальный Git.
- Не пытайся самостоятельно создавать публичный репозиторий без моего разрешения.
- Объясни, как подключить GitHub.
- Подготовь проект к публикации через GitHub Pages.

### Важное правило

Git-коммиты должны создаваться регулярно, а не только в конце разработки.

Если заканчиваются токены или контекст, сначала сохрани файлы, затем создай коммит всех безопасных завершённых изменений и обнови `PROJECT_PROGRESS.txt`.

Если коммит невозможен, обязательно сохрани изменения на диске и укажи причину в `PROJECT_PROGRESS.txt`.

**Моя цель: иметь историю всех важных изменений проекта, чтобы в любой момент можно было вернуться к предыдущей рабочей версии.**
